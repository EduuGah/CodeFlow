# Experiência de Aprendizado e Metodologia

## 1. Estrutura de Aulas
1. Objetivo e Explicação inicial.
2. Exemplo simples e visual.
3. Exercício guiado.
4. Exercício independente.
5. Desafio, Revisão e Próximo Passo.

## 2. Tipologia de Exercícios (Anti-Decoreba)
Variação extrema de contextos, valores e restrições. Tipos exigidos:
- Prever resultados / saída.
- Completar código / lógica.
- Arrastar e soltar blocos.
- Identificar e corrigir bugs (Debugging).
- Escrever código do zero.
- Desafios com restrições (Ex: "Resolva sem usar loops").
- Tradução de problema para pseudocódigo.

## 3. Sistema de Dicas Progressivas (Socrático)
Nunca entregar a resposta pronta imediatamente.
- **Dica 1:** Orientação conceitual / geral.
- **Dica 2:** Orientação específica.
- **Dica 3:** Parte da solução.
- **Dica 4:** Solução completa explicada.

## 4. Ferramentas Educacionais Avançadas
- **Modo "Trace" (Step-by-step):** Acompanhar a execução do código linha por linha com estado de variáveis.
- **Visualização de Memória:** Representações visuais de Arrays, Objetos e Call Stacks.
- **Laboratórios e Playgrounds:** Áreas livres para teste (HTTP, SQL, Git interativo).
- **Método Feynman:** Modalidade onde o aluno precisa "explicar" um conceito para avançar.
- **Flashcards e Repetição Espaçada:** Sistema de revisão baseado em performance e retenção.
- **Code Review Educacional:** Analisar Pull Requests com problemas estruturais e de qualidade.

## 5. Avaliação de Qualidade de Código (Pós-resolução)
Não basta o código funcionar. O feedback deve englobar:
- Legibilidade.
- Complexidade e Duplicação.
- Manutenibilidade e Boas práticas.
- Performance (Comparando soluções O(n) vs O(n²)).

## 6. O Papel da IA Tutora
- Fazer perguntas antes de responder.
- Guiar o raciocínio.
- Identificar nível do aluno.
- *Uso proibido:* Entregar resposta pronta ou ser muleta de código. Passa por validação rigorosa para evitar alucinações de conteúdo.
